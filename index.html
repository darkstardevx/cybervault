CLI — no session left unlocked

Every operation prompts
for the master password.

No unlocked session sits around anywhere to be stolen. add reads the secret from stdin if it's piped — the path Keysmith's --save flag uses — otherwise prompts interactively with hidden input.

TUI — unlock once

Browse, search, copy —
without re-entering the password.

Bare cybervault launches an interactive terminal UI. The derived key lives in memory only for the session and is gone the moment it exits.

While adding a new entry's secret, generate one on the spot with ctrl+g (password) or ctrl+p (passphrase) — both shell out to Keysmith, showing a live entropy estimate as you type a length or word count.

Threat model

Protects secrets at rest.
Nothing more, nothing less.

Someone with read access to the vault file — a stolen disk, another user on the machine, a leaked backup — can't read it without the master password. It does not protect against a keylogger, malware on an already-unlocked session, or someone watching you type it.

The vault file and its directory are locked to owner-only (0600/0700) on every save, not just at creation — a file that predates this or got loosened some other way self-heals on the next write.

~/.local/share/cybervault/vault.cvlt
perms
$ stat -c '%a %n' ~/.local/share/cybervault/*
0700 /home/user/.local/share/cybervault
0600 /home/user/.local/share/cybervault/vault.cvlt

# re-checked and re-applied on every write, not just init

Get CyberVault running

One command — downloads, verifies the checksum, installs to ~/.local/bin.

>_ curl -fsSL https://raw.githubusercontent.com/darkstardevx/cybervault/main/install.sh | sh

Installs cybervault. Works standalone — Keysmith is only needed for the TUI's ctrl+g/ctrl+p generate-in-place shortcuts.
